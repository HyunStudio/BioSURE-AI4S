# PDF spacing crosscheck — post-hoc development note (2026-10-03)

This change adds review-only, page-numbered word-spacing suggestions to the PDF importer. `pypdf` remains the source of the imported text. On pages with a spacing-fault signal, `pdfplumber` independently reads the same PDF bytes. BioSURE suggests a replacement word only when the non-whitespace characters match exactly and the primary text has a distinctive short-prefix or individually spaced-glyph fracture. It never changes imported text, invokes the paragraph repair gate, or treats parser agreement as source authentication.

The three previously frozen open-access publisher PDFs were inspected before this rule was written and therefore are **development cases**, not held-out validation. On the Nature article page 1, the importer now lists `f o r → for`, `d r u g → drug`, `d i s c o v e r y → discovery`, and `ef ficiency → efficiency`. These touch both scored Nature defects. The MDPI `faith-fully` and `de-tection` line-wrap defect remains outside the rule because deleting a hyphen can alter a legitimate compound. On the three-source scored set this is **two of three defective text units with a relevant suggestion, zero automatic restorations**. The correct-reference direct-copy comparator remains exact on all five scored units, including controls; this feature does not improve on that comparator.

Suggestions elsewhere on the same pages can be wrong. In particular the second parser sometimes concatenates ordinary adjacent words or author names; the short-fracture filter reduces but does not eliminate such candidates. The full-publisher-PDF importer caps the displayed hints at 64 across pages and warns when truncated, so these counts are not an estimate of recall or precision in unseen PDFs. A single development agent checked the above examples against the prior one-agent visual/JATS gold; there is no independent annotation, blinded source selection, timed reviewer study or clinical validation. A user must check the visible PDF and edit the field manually before acknowledging review.

Two additional PMC Cloud PDFs were named before running the crosscheck as **smoke sources only**: [PMC12838518](https://pmc-oa-opendata.s3.amazonaws.com/PMC12838518.1/PMC12838518.1.pdf), SHA-256 `754df75b0789e8f41651941adac72db20e97a8d08ed44059022e7f21a111426e`, and [PMC10879372](https://pmc-oa-opendata.s3.amazonaws.com/PMC10879372.1/PMC10879372.1.pdf), SHA-256 `ef9be4d0225061e6e407fc76bee175c12511c3f053921409aa34db8eccad95ff`. Both imported without parser failure. The former displayed no cross-parser spacing candidate; the latter displayed candidates such as `ef ficacy → efficacy` and reached the global hint cap. During inspection the latter also exposed false candidates formed by author names and neighboring words, prompting stricter filtering and regression tests. Neither PDF has independently transcribed defect gold here, so these imports do **not** establish sensitivity, precision or a competitive win.

Regression checks cover actual parser output on generated PDFs, candidate boundaries, non-spacing/hyphen controls, parser-failure fallback, literal browser rendering and retention of unchanged imported text. Reproduce with `python -m pytest tests/test_pdf_extract.py tests/test_web_pdf.py -q -p no:cacheprovider` and `node --test tests/test_browser_logic.js`. The previously frozen pilot decisions/results were not changed.
