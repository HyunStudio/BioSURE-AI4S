## Real extraction-error pilot — deliberately small

The PDF/text source is Tward et al., [DOI 10.1038/s41467-025-65317-7](https://doi.org/10.1038/s41467-025-65317-7), [PMCID PMC12645051](https://pmc.ncbi.nlm.nih.gov/articles/PMC12645051/), CC BY 4.0. The public [eScholarship full-PDF download](https://escholarship.org/content/qt8cc3z8ph/qt8cc3z8ph.pdf) has a repository cover: article page 1 is file page 2. The two-page excerpt begins at article page 1. Both locked PDF hashes, the pypdf 6.16.2 procedure, post-hoc selection and modified short text are recorded in [inputs](../fixtures/native_pilot_inputs.json). A separately stored [gold transcription](../fixtures/native_pilot_gold.json) was checked by one agent against rendered PDF and official JATS. This is not independent domain-expert adjudication. One title control and two actual article-page-1 text-layer errors come from **one article**, not three independent documents. The PDF, XML and figures are not distributed.

The decision command accepts inputs and a frozen model, **no gold argument**. It writes its decision file before the score command opens gold. The scorer checks the input and decision digests, case IDs, and whether each control/error label agrees with observed text versus gold. These hashes catch accidental switching or modification, but cannot prove authorship or prevent a person from recomputing a false fixture.

| Same three records | Exact automatic | Incorrect automatic | Abstentions | Native-error records needing review |
|---|---:|---:|---:|---:|
| BioSURE bounded workflow | 0 | 0 | 3 | 2/2 |
| Direct declared-reference copy | 3 | 0 | 0 | 0/2 |
| Normal diff / manual review | 0 | 0 | 3 | 2/2 |

The title control accounts for one of copy's three exact outputs. On the **two actual extraction-error records**, direct copy restores both when its reference is correct; BioSURE restores neither automatically. The diff exposes both discrepancies but writes no output. “Needs review” is a record count, **not measured time**. No policy demonstrated a comparative restoration or labor advantage here. The PDF-import figure-label loss remains outside this text-only scoring task.

The learned correspondence model is **not an independent error detector** in this pilot. Its previous `REVIEW` count inherited the diff's changed/not-changed flag, so that count has been removed. Both erroneous one-paragraph records have above-threshold match scores (0.981 and 0.938), and only the body record has lexical number/unit flags, potentially from citation and spacing artifacts. The title also matches above threshold. One reference per record makes ranking trivial. The model authorizes zero repairs, and these signals cannot be called 1/2 detection sensitivity or a model advantage.

To reproduce from the standalone root with Python 3.12, choose fresh output names:

```powershell
python scripts/evaluate_native_pilot.py decide fixtures/native_pilot_inputs.json fixtures/ml_model.json pilot-decisions.json
python scripts/evaluate_native_pilot.py score pilot-decisions.json fixtures/native_pilot_gold.json pilot-results.json
python scripts/verify_reproduction.py .
```

For source-to-fixture provenance, independently obtain the public full PDF from the article source, then run `python scripts/verify_native_source.py path/to/full-paper.pdf`. The command requires the frozen full-PDF SHA-256, extracts its article page 1 (file page 2), and confirms all three observed strings occur there. It also accepts the locked two-page excerpt (article page 1 is file page 1). It does **not** check visual truth, gold, random selection, or article licensing. The PDF itself is deliberately not in the ZIP; an arbitrary same-title PDF with different bytes will fail the hash check.

## Fixed two-source OoC publisher-PDF audit

The [internally fixed protocol](ooc-pdf-audit-protocol.md) selected **four preselected title/abstract units**—the complete title and abstract on the first publisher-PDF page of each [2017 multi-tissue chip paper](https://www.nature.com/articles/s41598-017-08879-x) and [2020 WAT-on-a-chip paper](https://www.nature.com/articles/s41598-020-63710-4). It was committed before inspecting those PDF text layers; it was not an external preregistration. Both source PDFs are CC BY 4.0 and their frozen SHA-256 digests, extraction anchors and short modified excerpts are in `fixtures/ooc_pdf_PMC5562747_inputs.json` and `fixtures/ooc_pdf_PMC7170869_inputs.json`. All four attempted units were scorable. The v0.3.4 correction preserves line-end hyphens instead of stripping them; the same article's publisher HTML and rendered page supplied one-agent gold. No PDF binary or figure was redistributed.

The earlier v0.3.3 importer deleted genuine line-end hyphens in `organ-on-a-chip`; its **two 2017 joined-word differences were introduced by BioSURE**, not by pypdf. After preserving the source glyphs, those title/abstract units are **2 controls**. The 2020 title and abstract remain **2 genuine pypdf text-layer error units**, with `WAt` where the rendered page and publisher HTML have `WAT`. Across all four units BioSURE restores **0/2 errors** automatically and abstains on **4/4**; direct copying the correct declared reference is exact on **4/4**. Normal diff flags **2/2 errors** for manual review but makes no replacement; the learned reviewer flags **0/2 errors** with lexical alerts and authorizes none. The 2017 correction is a pipeline bug fix, not evidence of BioSURE repair effectiveness. No review time was measured. The two papers were already part of the older constructed structural challenge, so the sources are not independent of all project development, although neither was in ML training. Source and gold remain the same article and adjudication was not independent expert review. Two papers and title/abstract-only selection cannot estimate deployment performance or scientific benefit.

The decision stage accepts the public input files and frozen model but no gold; the scoring stage then opens the separate gold files. Reproduce each source with `scripts/evaluate_native_pilot.py decide` and `score` using `fixtures/ooc_pdf_PMC5562747_{inputs,gold}.json` or `fixtures/ooc_pdf_PMC7170869_{inputs,gold}.json`. The offline verifier checks both sealed results. To verify observed text against an independently downloaded byte-matching publisher PDF, run `python scripts/verify_ooc_pdf_source.py source.pdf fixtures/ooc_pdf_PMC5562747_inputs.json` (or replace both PMCID names with PMC7170869). The PDF verifier checks PDF identity and text-layer observations only; it cannot certify visual gold, rights, reference authenticity, or sample representativeness.

## Additional fixed three-source cross-publisher audit

The [2026-10-03 protocol](three-source-ooc-pdf-audit-protocol.md) was committed before text-layer inspection. It locked title and abstract attempts on the first PDF page of three previously unused articles: [Wang et al.](https://www.nature.com/articles/s41378-025-00933-3), [Kanioura et al.](https://www.mdpi.com/2072-666X/16/7/740), and [Liu et al.](https://www.frontiersin.org/journals/oncology/articles/10.3389/fonc.2025.1602225/full). The official PMC Cloud metadata identifies CC BY open-access, non-manuscript, non-retracted deposited PDFs. The Frontiers publisher PDF is byte-identical to its deposit; publisher-byte identity remains unverified for Nature and MDPI because their direct downloads did not yield PDFs in this environment. Exact PDF and XML digests, extraction anchors and modified text units are frozen in the three `fixtures/ooc_pdf_PMC12*_inputs.json` files. Source PDFs, XML and rendered pages are not redistributed.

Of **six attempted units**, the Frontiers abstract continues onto page 2 and is **unscorable** under the first-page rule; its title remains. The other **five units** comprise two controls and three observed-versus-canonical discrepancies. Nature's title has severe text-layer letter spacing, and its abstract splits `efficiency` as `ef ficiency`. MDPI's abstract retains two discretionary *visible* line-wrap hyphens (`faith-fully`, `de-tection`) that are absent from the continuous JATS/HTML text; this is a reflow/normalization issue, **not evidence that pypdf hallucinated those glyphs**. Its title and the Frontiers title are controls. One development agent checked the rendered pages against JATS; no independent adjudicator was involved.

On the five scorable units, BioSURE makes **0 exact and 0 incorrect automatic repairs, abstaining on 5/5**. Correct-reference direct copy is **5/5 exact**; ordinary diff flags **3/3 discrepancies** for manual review but repairs none. The frozen learned reviewer emits lexical alerts on **1/3** discrepant units, with no automatic repair. These are tiny article-derived samples, not deployment sensitivity or proof of model benefit. The correct-copy comparator remains stronger on restoration accuracy; BioSURE's defensible value proposition is inspectable, bounded workflow, which still needs a timed same-input user study and reference-authentication process.

Run `python scripts/verify_reproduction.py .` to recompute sealed source results and the [aggregate](../results/three_source_pdf_audit.json). For source checks, obtain each exact PDF from the recorded PMC Cloud URL and run `python scripts/verify_ooc_pdf_source.py path/to/PMC12078732.pdf fixtures/ooc_pdf_PMC12078732_inputs.json` (similarly for PMC12300027 and PMC12158725). The title-only Frontiers verification is intentional; it does not turn the page-2 abstract into a scored unit. `scripts/build_three_source_pdf_audit.py` can regenerate fixtures with all six exact-hash PDF/XML inputs, but cannot independently establish visual gold.

## Reference-trust failure boundary

The authored stress test applies 36 candidates, of which **12 are wrong**: all twelve are forged-reference controls across twelve project-authored graphs. The strong whole-graph reconstruction comparator also fails those twelve. The denominator is a deliberately balanced test, **not** a real-world 12/36 error probability. The new native pilot does not resolve this vulnerability; direct copying would also be unsafe with a false reference.

**Precondition for any automatic use:** a responsible operator must independently establish the reference's provenance, version and exact document scope against the original authorized source before allowing its evidence into the workflow. If that cannot be established, leave the record in manual review; do not treat a digest, user acknowledgement, retrieval URL or this app's receipt as source authentication. The current API does not enforce that external check, so the present package is not safe as an unattended production repair service.

## Go / No-Go

**Go:** transparent Tool & Platform prototype submission, with the frozen results and all limits visible. **No-Go:** claim of first-place competitiveness, learned superiority, validated natural-error performance, clinical or OoC impact, expert endorsement, or safe unattended automatic correction. A stronger claim needs several independently selected native-error sources, adjudicators independent of development, same-input timed user comparison, and a verified reference-provenance workflow. No such study is claimed here.
