## What the bounded policy actually decides

The fixed fictional [policy-boundary audit](../results/policy_boundary_audit.json) replays five separated-label public-adapter contract checks and one **separately counted forged-reference control** with `python scripts/evaluate_policy_boundary.py verify --root .`. Unsupported replacement, stale structural mismatch, invented upstream wording, URL/digest-only declaration and an exact internal omission all abstain. The five contracts match their frozen expectations **5/5**; the forged but structurally matching reference also abstains, yielding **0/1 automatic repairs** in that separate control. The public API does not authenticate a reference's source or scope; it withholds trusted evidence from arbitrary inputs. Input, expectation, decisions, reason codes and receipt hashes are packaged separately. This is a policy regression, **not** a source-authentication guarantee or estimate of natural-error safety.

The [six fictional batch records](../fixtures/workflow_examples.json) give a reproducible, decision-level illustration, not a researcher study. The offline [reproduction verifier](../scripts/verify_reproduction.py) checks these exact outcomes: two bounded structural candidates are withheld from automatic application, one unchanged record is left unchanged, and three further records require manual review. In particular, `sample-substitution` does not let plausible replacement wording through; `sample-boundary` is outside the internal-omission rule; and `sample-ambiguous` has no uniquely supported missing position. The reviewer can see the input, changed location and decision receipt instead of accepting an opaque repaired document. These six authored examples measure policy behavior only; they establish neither fewer human errors nor faster review than ordinary diff or correct-reference copy.

| Record | Deterministic outcome | Operator decision supported |
|---|---|---|
| `sample-omission`, `sample-duplicate` | 2 bounded candidates, 0 automatic edits | Inspect the proposed difference and bound receipt; the declared reference is unverified. |
| `sample-unchanged` | 1 unchanged record | Avoid inventing a repair for identical inputs. |
| `sample-substitution`, `sample-boundary`, `sample-ambiguous` | 3 further manual-review records | Do not auto-apply unsupported, boundary, or ambiguous edits. |

## Real extraction-error pilot — deliberately small

The PDF/text source is Tward et al., [DOI 10.1038/s41467-025-65317-7](https://doi.org/10.1038/s41467-025-65317-7), [PMCID PMC12645051](https://pmc.ncbi.nlm.nih.gov/articles/PMC12645051/), CC BY 4.0. The public [eScholarship full-PDF download](https://escholarship.org/content/qt8cc3z8ph/qt8cc3z8ph.pdf) has a repository cover: article page 1 is file page 2. The two-page excerpt begins at article page 1. Both locked PDF hashes, the pypdf 6.16.2 procedure, post-hoc selection and modified short text are recorded in [inputs](../fixtures/native_pilot_inputs.json). A separately stored [gold transcription](../fixtures/native_pilot_gold.json) was checked by one agent against rendered PDF and official JATS. This is not independent domain-expert adjudication. One title control and two actual article-page-1 text-layer errors come from **one article**, not three independent documents. The PDF, XML and figures are not distributed.

The decision command accepts inputs and a frozen model, **no gold argument**. It writes its decision file before the score command opens gold. The scorer checks the input and decision digests, case IDs, and whether each control/error label agrees with observed text versus gold. These hashes catch accidental switching or modification, but cannot prove authorship or prevent a person from recomputing a false fixture.

| Same three records | Exact automatic | Incorrect automatic | Abstentions | Native-error records needing review |
|---|---:|---:|---:|---:|
| BioSURE bounded workflow | 0 | 0 | 3 | 2/2 |
| Direct declared-reference copy | 3 | 0 | 0 | 0/2 |
| Normal diff / manual review | 0 | 0 | 3 | 2/2 |

The title control accounts for one of copy's three exact outputs. On the **two actual extraction-error records**, direct copy restores both when its reference is correct; BioSURE restores neither automatically. The diff exposes both discrepancies but writes no output. “Needs review” is a record count, **not measured time**. No policy demonstrated a comparative restoration or labor advantage here. The PDF-import figure-label loss remains outside this text-only scoring task.

The learned correspondence model is **not an independent error detector** in this pilot. Its previous `REVIEW` count inherited the diff's changed/not-changed flag, so that count has been removed. Both erroneous one-paragraph records have above-threshold match scores (0.981 and 0.938), and only the body record has lexical number/unit flags, potentially from citation and spacing artifacts. The title also matches above threshold. One reference per record makes ranking trivial. The model authorizes zero repairs, and these signals cannot be called 1/2 detection sensitivity or a model advantage.

To reproduce from the standalone root with Python 3.12, choose fresh output names:


For source-to-fixture provenance, independently obtain the public full PDF from the article source, then run `python scripts/verify_native_source.py path/to/full-paper.pdf`. The command requires the frozen full-PDF SHA-256, extracts its article page 1 (file page 2), and confirms all three observed strings occur there. It also accepts the locked two-page excerpt (article page 1 is file page 1). It does **not** check visual truth, gold, random selection, or article licensing. The PDF itself is deliberately not in the ZIP; an arbitrary same-title PDF with different bytes will fail the hash check.

## Learned upstream proposal on the same locked sources

The bundled logistic model was fitted earlier on 12 CC BY 4.0 article sources, tuned on six other sources and evaluated on six held-out constructed-variant sources; none of those 24 sources occurs in the eight-source extraction audit. No new DL model was trained. Here the model receives each selected paper's two observed PDF-text units together with its two declared JATS reference units. It ranks title/abstract correspondence, requires both matches above its frozen 0.8 threshold, unambiguous and in order, then proposes the *entire declared reference sequence* for a separate deterministic gate check. Thus the model aligns units; it does not generate corrected scientific prose. The gate made **zero automatic repairs** on these real-source cases.

Two failures are visible rather than omitted: `PMC12864593` (development) and `PMC12789962` (held-out) each have one wrong top rank; both sources triggered proposal abstention from low confidence/ambiguity. The reversed title/abstract mapping is a deliberately wrong sanity control, not a safe-use comparator. `difflib` and token Dice outperform the fitted ranker on this tiny, selected task; no learned superiority, improved accuracy, research-time saving or first-place readiness follows. Because every source is represented by only a title and abstract and the same article provides reference and gold, these counts are not a deployment estimate. ## Reference-trust failure boundary

The authored stress test applies 36 candidates, of which **12 are wrong**: all twelve are forged-reference controls across twelve project-authored graphs. The strong whole-graph reconstruction comparator also fails those twelve. The denominator is a deliberately balanced test, **not** a real-world 12/36 error probability. The new native pilot does not resolve this vulnerability; direct copying would also be unsafe with a false reference.

**Precondition for any automatic use:** a responsible operator must independently establish the reference's provenance, version and exact document scope against the original authorized source before allowing its evidence into an independently controlled workflow. The current public API does not perform or accept such authentication and selects no corrected output. A digest, user acknowledgement, retrieval URL or this app's receipt is not source authentication. This package is not an unattended production repair service.

## Go / No-Go

**Go:** transparent Tool & Platform prototype submission, with the frozen results and all limits visible. **No-Go:** claim of first-place competitiveness, learned superiority, validated natural-error performance, clinical or OoC impact, expert endorsement, or safe unattended automatic correction. A stronger claim needs several independently selected native-error sources, adjudicators independent of development, same-input timed user comparison, and a verified reference-provenance workflow. No such study is claimed here.

Registration readiness: **Go for the published project package**, conditional on the owner supplying true contact/account details. Final-submission readiness: **conditional**, because neither the required registration receipt nor a submitted Kaggle Writeup has been verified. Winner readiness: **No-Go on current evidence**. These are different gates; passing software tests does not change the latter two.
