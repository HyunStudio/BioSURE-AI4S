## Project summary

Life-science pipelines depend on research-document text. A structurally plausible repair can still replace the wrong paragraph. BioSURE provides an offline workbench for inspecting one proposed internal omission or extra exact duplicate against a declared reference, and otherwise defers to manual review. Because the public path cannot authenticate that reference, it now abstains even for bounded candidates and selects no corrected graph. A receipt binds the supplied request, candidate, evidence, rule version and decision.

The tool processes actual paragraph input, shows difference locations and exports JSON. Batch triage distinguishes unchanged from review-required records without overwriting source files; it selects no corrected public-input text. A provider-independent path checks pasted upstream proposals against the declared reference and observed text, marks a bounded exact match for review and rejects invented wording. The bundled logistic model aligns units and copies declared-reference text as an upstream candidate, but cannot authenticate it or authorize repair. These are integration and selected-source demonstrations, not a measured benefit to research outcomes.

The separate, lower-level fixed structural benchmark—not the arbitrary public-input workflow—has eight synthetic cases from two graphs with two exact corrections and six abstentions, plus nine article-derived cases from three CC BY 4.0 OoC articles with three exact corrections and six abstentions. An independent whole-graph comparator using the same supplied evidence ties both sets. A 168-case authored stress suite exposes twelve incorrectly applied outputs when that evidence is forged. These are structural gate experiments, not proof of source authentication, deployment safety or algorithmic superiority.

BioSURE's contribution is an inspectable, reproducible workflow tool with explicit limits and a review-only learned matcher, not a learned biological predictor or source-authentication system. Clinical use, semantic verification, natural-defect effectiveness and researcher time savings remain outside the demonstrated scope.

## Technical report

### 1. Problem and application scenario

A researcher or pipeline maintainer has a canonical paragraph sequence and a converted sequence of an OoC methods/results record. A conversion fault removes a methods paragraph or inserts an extra copy. A repair component may suggest an edit that is plausible in shape but not supported in content. The task is to inspect the proposed changed payload and decide whether exactly one bounded edit is consistent with the declared reference.

The included workflow examples are explicitly fictional, not actual lab incidents. The original article structural probe uses research-document structure reduced to hashes; a separate 24-article CC BY 4.0 corpus supplies attributed paragraph excerpts for the learned matcher. Neither processes experimental measurements. The current workbench is intended for local research-document QA upstream of analysis or AI-assisted research support. The learned component performs local correspondence inference but has no repair authority. Tool & Platform describes the current contribution more accurately than a novel-model claim.

### 2. System and decision boundary

The graph request has exactly four fields: `case_id`, `damaged`, `candidates`, and `evidence`. Ordered blocks contain an ID, type, SHA-256 text digest, heading level and optional target. Citation anchors, if present, must resolve. Strict parsing rejects extra nested fields, invalid identities/hashes and outcome labels. Clean gold and corruption specifications are not decision inputs.

For insertion, a candidate differs by exactly one canonical paragraph. Its ID and hash must match an evidence entry; both surviving neighbor IDs must match the insertion position. For duplicate removal, the retained and removed identities and equal paragraph digest must match the declared identity evidence. Unrelated changes, contradictory evidence, absent support or multiple supported candidates cause abstention. The frozen rule is `biosure-blind-v2`. It is not a trained confidence score or calibrated statistical guarantee.

The paragraph adapter collapses whitespace and assigns stable reference IDs from unique paragraph digests. It proposes at most one bounded structural edit, but does not turn a caller-supplied reference into trusted evidence; the public response abstains and has null selected output. Repeated reference content, boundary omission, substitution, reordering and multiple faults are unsupported even as bounded candidates. Difference hunks help manual inspection but never authorize an edit. Hunk spans are zero-based and half-open in JSON; the UI shows human-readable paragraph positions.

The upstream proposal adapter accepts the same declared reference and observed sequences plus `proposed_paragraphs`. It maps the actual proposal hashes into a candidate graph and invokes the unchanged v2 structural gate without inventing trust from the caller's text. An exact bounded match is marked review-required, while invented wording is rejected; neither is applied. A proposal receipt binds reference, observation, actual proposal and gate receipt digests under `biosure-proposal-v1`; origin remains unauthenticated. This is a deterministic review boundary for externally supplied output, not a learned detector or a demonstration that a named AI produced it.

Batch input is an array of 1–100 workflow records with unique IDs. Validation completes before output creation; an invalid later item yields no partial output. The browser imports a local JSON file or accepts pasted JSON, displays per-record decisions and downloads the result. Editing/clearing invalidates stale results. CLI batch writes one explicitly selected new JSON file and never replaces an existing path. The summary separates unchanged records from automatic corrections and manual-review records. The HTTP limit is 1 MiB; the CLI limit is 8 MiB.

The learned matcher is regularized logistic regression over eight lexical features, fitted deterministically on authored pair labels from attributed CC BY 4.0 article paragraphs. Its output ranks candidate reference matches and flags lexical number/unit/negation differences. The new upstream path requires every match to exceed the frozen threshold, be unambiguous and preserve unique unit order; otherwise it abstains. If eligible, it copies the whole declared-reference sequence as a candidate and invokes the unchanged proposal gate. The ordinary workflow decision is retained under `original_workflow_review` only for comparison; it is not the learned proposal's selected output. Only a non-null `proposal_check` may select output for this path. This is learned alignment, **not model-generated scientific correction**; the existing gate remains the sole edit authority. The full-article source split, dev-only threshold selection, fixed model and competing exact/difflib/token-Dice/lexical-blend scores are reproducible offline. Probabilities are not calibrated biological confidence. PDF import uses BSD-licensed `pypdf`, limits input to 16 MiB/32 pages, stores no PDF bytes and returns page-text chunks with null bounding boxes and explicit reading-order/paragraph-boundary warnings. Figure text is not OCRed, and a separate UI acknowledgement is required after manual page comparison. The response also provides capped, page-numbered review-hint excerpts for spacing artifacts and preserved line-end hyphens; the UI shows them as literal text, not verified defect locations. These chunks are not automatically accepted as paragraph segmentation.

### 3. Receipts, privacy and trust

Canonical UTF-8 JSON is hashed to record input, evidence, candidates, configuration and selected graph. The same input yields the same decision receipt. Receipts provide content binding and replayability, not a signature, timestamp authority, authenticity proof or biological truth guarantee. A third party able to change a reference and recompute hashes can still create a consistent false result.

The browser server binds only to loopback, checks local Host and same Origin, rejects malformed/duplicate-key/non-finite JSON and applies a one-MiB JSON body limit, with a separate 16-MiB PDF endpoint. Paragraph limits are 128 per sequence, 4096 characters each and 262144 normalized characters combined. Advanced graph requests have at most 32 candidates, 128 blocks per graph and 256 evidence entries. Inputs are processed in memory without server-side input storage or prose access logging. Explicit downloads contain user text. Clearing a browser view is not secure erasure. The server is not a production-hosting or clinical deployment system.

### 4. Data and evaluation design

The authored synthetic challenge has two graphs and eight deliberately selected conditions, including valid insertion/removal, wrong content/position/identity, missing evidence and two separately supported insertion alternatives. It is exploratory, not a confirmatory statistical sample.

The separate structural article-derived probe uses official PMC OAI-PMH JATS for [PMC5562747](https://pmc.ncbi.nlm.nih.gov/articles/PMC5562747/), [PMC7170869](https://pmc.ncbi.nlm.nih.gov/articles/PMC7170869/) and [PMC6745596](https://pmc.ncbi.nlm.nih.gov/articles/PMC6745596/). Each source explicitly declares CC BY 4.0. The generator selects the first three nonempty body paragraphs, collapses whitespace and keeps only digests and structural locators. It constructs three cases per source. Reference and gold come from the same JATS; this is not independent adjudication or native-defect discovery. This older structural probe packages no article prose. The separate ML corpus *does* package 192 attributed CC BY 4.0 paragraph excerpts from 24 articles, with names, titles, DOI, links, license and change notice in its records; no full XML/PDF, figures or patient data are packaged.

The stress suite uses twelve authored graphs with 16/32/64 paragraphs and fourteen conditions per source: valid edits, no change, missing evidence, wrong hash/ID/location, extra metadata, unrelated edits, conflicting evidence, ambiguity, forged evidence, wrong retained identity and reordered context. There are 168 cases but twelve source graphs. The conditions are intentionally balanced negative controls, not estimates of deployment prevalence.

The evaluator records outcome-free decisions before opening clean gold, then checks the complete selected graph. Gold separation prevents decision-path leakage; it does not create independent source evidence. All sets remain separate. The source count is reported alongside case count.

Identity proposes no correction. A weak schema/locality comparator accepts executable bounded graph edits without evidence validation. Hash-only matching receives the same evidence but checks only changed hashes. Independent whole-graph reconstruction receives the same evidence and builds canonical allowed one-edit graphs without calling BioSURE's validators or imposing its global conflict veto.

BioSURE rejects four weak-baseline errors in the tiny synthetic probe and three in the article probe, but those wins do not prove novelty. Equal-evidence reconstruction ties both and corrects twelve additional stress cases with conflicting evidence. The conservative veto reduces coverage in that condition. Every BioSURE stress error occurs when both candidate and declared evidence are forged while gold stays unchanged; both strong methods fail all twelve forged-reference controls. This directly exposes the assumption boundary. It must not be advertised as a measured real-world 33% error rate or concealed in a headline of zero errors.

Six fictional actual-text public workflow examples give zero automatic corrections, one unchanged record and five review-required records. Two review records include bounded edit candidates; none receives a selected corrected output. They demonstrate interface and triage behavior only, not an OoC user study. Automated package tests exercise implementation contracts, malformed inputs, privacy boundaries and reproduction, not scientific validity.

The learned correspondence experiment uses 12 training, six development and six held-out article sources (4,584 training pairs). The held-out set has 284 constructed queries. Eight held-out unit-change controls exercise the lexical unit alert, but no natural unit-error sensitivity is inferred. Relative to the strongest lexical baseline, top-1 accuracy difference is 0.000, with article-bootstrap 95% interval [0.000, 0.000]. ### 6. Practical value and honest limits

Earlier usability work prevents asynchronous sample/file loads from being discarded by acknowledgement and exposes numbered text plus change spans in every batch record. The current proposal path is exercised by offline function, HTTP, CLI and browser tests: an exact bounded insertion/removal is identified for review, while invented wording and unrelated or unsupported changes are rejected. No public-input proposal is automatically selected. These are authored implementation controls, not independently sampled model outputs.

| Alternative | Complete correct reference available | Unsupported original difference | Audit boundary |
|---|---|---|---|
| Direct reference copy | Restores the reference immediately | Replaces the whole document regardless of scope | No bounded decision is required |
| Apply upstream proposal unchecked | Depends on the proposal, including invented text | Applies all supplied changes | No content-evidence gate |
| BioSURE upstream proposal check | Flags the bounded one-edit match for review; applies none | Withholds automatic replacement | Actual candidate and declared evidence are content-bound but source-unverified |

This comparison describes policy, not measured superiority. Direct copying remains simpler for complete replacement; BioSURE's restricted policy intentionally withholds some proposals that would equal the reference. A normal diff also displays changes. Neither user time savings nor downstream AI/research accuracy has been measured.

The potential benefit is inspectable change review, fail-closed public-input policy, local batch triage and reproducible decision records. A complete correct reference can simply be copied, so the paragraph adapter has no demonstrated restoration-accuracy advantage over copying. Both the post-hoc JHU pilot and fixed OoC audit confirm that limit in their selected units. We have not measured researcher time savings or compared usability against a normal diff viewer. The [practical validation protocol](https://github.com/HyunStudio/BioSURE-AI4S/blob/main/report/practical-validation.md) specifies the missing larger evaluation; the [official-criteria scorecard](https://github.com/HyunStudio/BioSURE-AI4S/blob/main/report/public-scorecard.md) records a Go for transparent prototype submission and No-Go for any first-place, learned-superiority or safe-unattended-use claim.

The tool can flag lexical differences in numbers, units and negation but cannot validate their scientific meaning or correctness. It cannot validate doses, treatment labels, figures, biological outcomes, clinical facts or translation quality. It does not authenticate evidence or detect arbitrary unknown defects. The constructed ML corpus has 24 sources; the structural probes still have only two/three/twelve sources. Domain benefit and integration into actual AI-assisted research workflows remain unvalidated. These limitations constrain the present contribution rather than being solved by the Tool & Platform label.
